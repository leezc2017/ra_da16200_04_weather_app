# DA16200 AT 命令 ③：访问心知天气获取 JSON

> 前置条件（**[M] 手册明文要求**）：**模组必须已连上 AP**。
> 原文：`AT+NWHTC` — *Prerequisite: The DA16200/DA16600 should be connected to AP.*
> 证据等级标记（[M]/[L]/[L2]）同 ① 文档第 0 节。

---

## 1. 完整可复制序列（取心知数据）

```
AT
AT+WFSTA                                  ← 期望 +WFSTA:1 + OK
AT+NWIP                                   ← 期望 +NWIP:0,<有效IP>,...
AT+NWHOST=api.seniverse.com               ← DNS 预检，期望 +NWHOST:<ip>
AT+NWHTC=http://api.seniverse.com/v3/weather/now.json?key=<REDACTED_API_KEY>&location=ip&language=zh-Hans,get
```

**成功判据：一条命令要回满三段**

```
① OK                                  ← 命令被接受（立即）
② HTTP/1.1 200 OK                     ← HTTP 状态行
   Date: ...
   Content-Type: application/json; charset=utf-8
   Content-Length: 256
   ...（若干响应头）
   {"results":[...]}                   ← 真正的 JSON 正文
③ +NWHTCSTATUS:0                       ← 事务结束，0 = 成功
```

> **只收到 `OK` 不算成功**，`OK` 只代表"命令被接受了"。
> **必须等到 `+NWHTCSTATUS:0` 才算这次 HTTP 事务完成。**

## 2. `AT+NWHTC` 语法

### 2.1 手册定义

**[M] Rev.3.5, 5.6.2 HTTP-Client Commands, Table 22（PDF 第 97 页）**

```
AT+NWHTC <url>,<method>(,<body>)
  <url>    : HTTP server address
  <method> : GET, POST or PUT
  <body>   : Body for POST and PUT methods, omitted for other methods.
             For JSON type, enclose the message with the single quotation — <'body'>

Prerequisite
  The DA16200/DA16600 should be connected to AP.

Example 1:
  AT+NWHTC=http://httpbin.org/get,get
  OK

Example 2:
  AT+NWHTC=http://httpbin.org/post,post,HTTP-Client POST method sample test!
  OK

For JSON type:
  AT+NWHTC=http://httpbin.org/post,post,'{  username: "aaa",  password: "1234"}'
  OK

Note:
  · Enabled by default in the SDK v3.2.3.0 or later.
  · If __SUPPORT_HTTP_CLIENT_FOR_ATCMD__ is enabled in the SDK, this command should be enabled.
```

### 2.2 模组自己的 HELP（**最贴近本机固件**）

**[L] `AUTO.txt` L265-268 实测**

> 即本机固件的三种 `option`：**`get` / `post` / `put`**（全小写）。

### 3.3 单引号包裹 URL 也行（风险#3 对照实验）

```
[AT>] AT+NWHTC='http://api.seniverse.com/v3/weather/now.json?key=<REDACTED_API_KEY>&location=ip&language=zh-Hans',get
[WIFI] OK

```

**结论（[L] 实测三组对照）**

| 实验 | 形式 | 结果 |
| --- | --- | --- |
| HTTP1 | 裸 URL（`&` `?` 不转义） | `res=OK nwstatus=0 len=690 body_len=274` |
| HTTP2 | 单引号包裹 URL | `res=OK nwstatus=0 len=690 body_len=274`（**与 HTTP1 完全一致**） |
| HTTP3 | `daily.json` 大包 | `res=OK nwstatus=0 len=1422 body_len=1006` |

> **`?` 和 `&` 不需要转义**，直接写即可。两种写法结果相同，任选。

## 4. 解析要点（[L] 实测结论）

固件侧 probe 给出的判定：

```
[PROBE] risk#1 verdict: hdr_sep=1 => MUST split CRLFCRLF before cJSON;
[PROBE]                json_direct=1 => body feeds cJSON with no cleanup;
[PROBE]                nwstatus=0 => HTTP transaction OK.

[PROBE]   hdr_sep=1 http='' body_off=416 body_len=1006 nlines=2
[PROBE]   json_direct=1 lead='{'
```

| 结论 | 说明 |
| --- | --- |
| `hdr_sep=1` | 头和体之间**有** `CRLFCRLF` 分隔 → **喂 cJSON 之前必须先切掉响应头** |
| `json_direct=1`、`lead='{'` | 切完之后正文直接就是 `{` 开头的合法 JSON，**不需要再做清洗** |
| `nwstatus=0` | HTTP 事务成功 |

**⚠️ 不要用 `Content-Length` 去截断正文**

| 接口 | `Content-Length`（HTTP 头） | 固件实测 `body_len` | 差值 |
| --- | --- | --- | --- |
| `now.json` | 256 | 274 | +18 |
| `daily.json` | 988 | 1006 | +18 |

两者**不一致（固定差 18 字节）**——模组是**按行**把响应吐到 UART 的，行边界会改写分隔字节。
**解析必须以 `hdr_sep` 分割后的实际接收 buffer 为准，不要拿 `Content-Length` 当长度。**

**响应缓冲**：`AT_RESP_BUF_SIZE`（`weather_http.c`）要能装下头+体。
实测 `daily.json` 总 `len=1422`；心知各接口正文均在 1 KB 量级，4096 字节足够，但**如果换成更大接口（如 `daily.json` 全字段 / 空气质量）要重新评估**。

## 5. `+NWHTCSTATUS` 状态码

**[M] Appendix B「HTTP Client Return Values」（PDF 第 151 页）**

### B.1 Table 55 — HTTP Client 定义值

| 值 | 宏 | 含义 |
| --- | --- | --- |
| **0** | `HTTPC_RESULT_OK` | **成功** |
| 1 | `HTTPC_RESULT_ERR_UNKNOWN` | 未知错误 |
| 2 | `HTTPC_RESULT_ERR_CONNECT` | 连接失败 |
| 3 | `HTTPC_RESULT_ERR_HOSTNAME` | 主机名解析失败（DNS） |
| 4 | `HTTPC_RESULT_ERR_CLOSED` | 连接被对端关闭 |
| 5 | `HTTPC_RESULT_ERR_TIMEOUT` | 超时 |
| 6 | `HTTPC_RESULT_ERR_SVR_RESP` | 服务器响应异常 |
| 7 | `HTTPC_RESULT_ERR_MEM` | 内存不足 |
| 8 | `HTTPC_RESULT_LOCAL_ABORT` | 本地中止 |
| 9 | `HTTPC_RESULT_ERR_CONTENT_LEN` | Content-Length 不符 |

### B.2 Table 56 — LWIP HTTP 定义值

| 值 | 宏 | | 值 | 宏 |
| --- | --- | --- | --- | --- |
| 0 | `ERR_OK` | | -9 | `ERR_ALREADY` |
| -1 | `ERR_MEM` | | -10 | `ERR_ISCONN` |
| -2 | `ERR_BUF` | | -11 | `ERR_CONN` |
| -3 | `ERR_TIMEOUT` | | -12 | `ERR_IF` |
| -4 | `ERR_RTE` | | -13 | `ERR_ABRT` |
| -5 | `ERR_INPROGRESS` | | -14 | `ERR_RST` |
| -6 | `ERR_VAL` | | -15 | `ERR_CLSD` |
| -7 | `ERR_WOULDBLOCK` | | -16 | `ERR_ARG` |
| -8 | `ERR_USE` | | -17/-18 | `ERR_UNKNOWN` / `ERR_NOT_FOUND` |

**判读**

| 现象 | 含义 | 下一步 |
| --- | --- | --- |
| 有 `OK`，但**始终等不到** `+NWHTCSTATUS` | 事务挂住 | 查是否连上 AP（`-6` 前置条件）；查 DNS |
| `+NWHTCSTATUS:0` | ✅ 成功 | 解析正文 |
| `+NWHTCSTATUS:3` | DNS 解析失败 | 查 `AT+NWHOST=api.seniverse.com` |
| `+NWHTCSTATUS:2` / `4` | 连接失败 / 被关闭 | 查出网、查 `AT+NWPING` |
| `+NWHTCSTATUS:5` | 超时 | 查链路质量 |
| `ERROR:-6`（命令本身就报） | **未连接到 AP** | 回到 ① 文档 |
| `ERROR:-8` | 响应缓冲区溢出 | 加大 `AT_RESP_BUF_SIZE` |
| `ERROR:-10` | 命令超时 | 加大超时 |

> ⚠️ **注意区分两类码**：`ERROR:-x` 是**命令执行阶段**的错（Appendix I, Table 58），
> `+NWHTCSTATUS:x` 是**HTTP 事务阶段**的码（Appendix B, Table 55/56）。两者体系不同，别混用。

## 6. HTTPS / SNI / ALPN 相关命令

**[M] Rev.3.5 p.97-100**

| 命令 | 语法 | 说明 | 本机支持 |
| --- | --- | --- | --- |
| `AT+NWHTCSNI` | `AT+NWHTCSNI=<sni>`，读 `AT+NWHTCSNI` | 设 Server Name Indication。**必须在连服务器之前设好**，**存 NVRAM** | ✅ 在命令表 |
| `AT+NWHTCALPN` | `AT+NWHTCALPN=<alpn_number>,<alpn1>[,<alpn2>,<alpn3>]`<br>例：`AT+NWHTCALPN=1,http/1.1` | ALPN 协商，**存 NVRAM**，连服务器前设 | ✅ 在命令表 |
| `AT+NWHTCSNIDEL` | `AT+NWHTCSNIDEL` | 删已存 SNI | ✅ 在命令表 |
| `AT+NWHTCALPNDEL` | `AT+NWHTCALPNDEL` | 删已存 ALPN | ✅ 在命令表 |
| `AT+NWHTCH` | `AT+NWHTCH=<url>,<method>`，响应多一层 `+NWHTCDATA:<size>,` 前缀 | HTTPS 变体 | ❌ **不在本机命令表** |
| `AT+NWHTCTLSAUTH` | — | TLS 鉴权 | ❌ **不在本机命令表** |

> **本机走 `http://`（已实测通），不要用 `https://` 相关变体。**
> 本工程的 API 走明文 HTTP 是 [L] 已验证可用的路径。

## 7. 心知 API 使用约束（[L] 从响应头读出）

| 响应头 | 值 | 含义 |
| --- | --- | --- |
| `x-ratelimit-limit` | `20;w=60` | **20 次 / 60 秒** |
| `x-ratelimit-remaining` | `19` → `18` → `17`（连续调用递减） | 剩余配额 |
| `x-ratelimit-reset` | `60.000` / `59.816` / `59.644` | 配额窗口重置倒计时（秒） |
| `Content-Type` | `application/json; charset=utf-8` | 按 UTF-8 解 |

**⇒ 取数间隔应 ≥ 3 秒**（20 次/60s），否则会被限流。

**[L] 探针实测的三次连续调用**

```

HTTP2  x-ratelimit-remaining: 18
HTTP3  x-ratelimit-remaining: 17

## 10. ⚠️ 当前阻塞点

**[L2]** `serial_capture.log`（21:36）显示阶梯卡在 **第 1 步**：

```
[AT>] AT+WFSTA        → [WIFI] ERROR:-5
[AT>] AT+WFCAP        → [WIFI] ERROR:-5
[AT>] AT+WFJAPA=...   → [WIFI] ERROR:-5
[AT>] AT+TIME         → [WIFI] +TIME:1970-01-01,08:36:21 / OK   ← 引擎是活的

`ERROR:-5 = Unsupported function`（[M] p.162），**不是密码错、不是没连上（那是 -6）、不是模式错（那是 -100）**。
根因未定，**按 `AT_01_连接WiFi.md` 第 4 节的决策树排查**（`AT+` → `AT+WFSCAN` → `AT+WFMODE` → `AT+WFDIS=?` → `AT+RESTART`）。

> 第 1 步不过，第 3 步无从谈起。**先把 `AT+WFSCAN` 能不能列出 AP 测出来**，那是最关键的分流点。
